# Openclaw 使用心得：我的智能助理实践与探索

## 引言

这个春节假期我深度使用了下openclaw，结果非常惊艳。但是在使用的过程中也遇到了很多问题。趁着使用体验和踩坑经历还记忆犹新，现在记录下我在使用过程中的经验教训并分享给大家，希望能对大家有所帮助。

首先给还不熟悉的同学简单介绍下openclaw：

OpenClaw 是 Peter Steinberger 于 2026 年 1 月发布的开源 AI 代理框架，旨在赋能用户构建和管理个性化智能助手。该框架可在本地设备上自主执行邮件管理、日程安排、应用控制等多种任务，并支持 WhatsApp、Telegram、Discord 等多平台集成。其最大特点是完全本地化运行，确保数据不出设备，且无需人工逐条确认即可实现自主操作。

OpenClaw 的核心在于提供高度可定制的自动化与智能化服务。用户不仅可以通过内置文档进行交互操作，甚至能自行创建运维工具，并利用 Lobster 等插件扩展功能。项目发布首周即获得超过 200 万的仓库访问量，迅速成为 GitHub 上的热门开源项目。

此外，OpenClaw 的生态系统日益完善，拥有 Clawhub 供用户获取各类技能，支持 Antfarm 智能体工作流，并内置 Labcrl 工具，共同构建了一个自进化的内容生态。

总而言之，OpenClaw 不仅能高效处理日常事务，更可作为您的专属智能体，助您实现复杂工作流的自动化和信息管理，带来前所未有的自由度和控制力。

接下来我将详细说明下我对openclaw的一些理解和实践操作说明。



## 一、Openclaw 核心能力解析

### 1.1 Openclaw 能干什么？

首先让我们看一下用openclaw都能干些什么事情，与提起ai agent不同，openclaw没有所谓的执行mode，它在本地运行本身即拥有与用户等同的执行权限，其在我们电脑上可以执行任务操作而无需我们的批准。其次它在agent层之上构建了一个gateway来维护与cli直接的交互，同时维持和飞书、whatsapp、telegram等客户端的连接，让我们可以通过这些通信软件方便的与本地的openclaw进行沟通。最后openclaw基于开源的pi agent构建支持工具调用，并增加了记忆、身份认知等支持，也就是说它可以自己根据交流的内容进行自主学习,优化回答和行为逻辑。

openclaw的架构非常简单，下面是openclaw github首页的简短的系统架构图，从图中可以看到，openclaw实现了一个gateway作为控制平面，将前端通信软件的消息通过websocket转发给后端的agent，而openclaw的agent则主要基于开源的pi agent实现，并自己实现了session管理、消息队列、记忆系统、tui和node等功能。

```
WhatsApp / Telegram / Slack / Discord / Google Chat / Signal / iMessage / BlueBubbles / Microsoft Teams / Matrix / Zalo / Zalo Personal / WebChat
               │
               ▼
┌───────────────────────────────┐
│            Gateway            │
│       (control plane)         │
│     ws://127.0.0.1:18789      │
└──────────────┬────────────────┘
               │
               ├─ Pi agent (RPC)
               ├─ CLI (openclaw …)
               ├─ WebChat UI
               ├─ macOS app
               └─ iOS / Android nodes
```

这意味着，你可以通过飞书等即时通讯软件通过openclaw完全控制自己的电脑，帮助自己处理工作、回复邮件、订阅通知、阅读文章、甚至开发项目。作为7\*24小时的个人助理，可以在你睡觉的时候，帮你完成白天安排的工作。

openclaw还有一个值得称道的特性，其他大部分的agent都只能接受指令，不能主动触发通知。而openclaw通过cron定时器和渠道交互能力实现了主动的触达，这一点我认为是个人助理必不可少的能力。

在大概一周的深度使用中，我实现了如下功能：

* 基于飞书、whatsapp的智能对话,支持语音消息交互
* 每天定时从rss信息源中筛选最新的文章并进行总结，之后推荐最有价值的文章发给我进一步阅读
* 接入moltbook阅读热门帖子，学习其中的agent技巧并更新memory
* 每天晚上基于这一天的工作内容学习处理原则并更新memory
* 自动集成antfarm 编程skill、自主接入clawhub并实现skill安全审计
* vibe coding实现论文abstract抽取入库并提供组合检索能力
* 自己实现了新的gateway维护方式，重启后自动触发任务继续执行

在一周的时间内，我的openclaw开发了大量的工具脚本，学会了\`工具优先原则\`、\`静默运行原则\`、\`成本优先\`等原则。



### 1.2 自运维能力

不过由于是开源工具且作为常驻电脑的个人助理，需要自己进行部署配置。但是不用担心，openclaw内置了全部的说明文档，只要安装官网完成简单的安装，剩下的所有事情都可以通过和openclaw对话的方式完成。得益于这样的方式，我在探索openclaw的功能是完成是通过一边交流一边看官网说明完成的，大部分情况下openclaw都能正确的实现并更新自己的配置，我称之为“自运维”特性。用户可以深入参与到助理的构建和维护中，实现更高程度的定制化和自主管理。

这里实践下来，虽然openclaw自运维能力很强，通过自然语言交互即可以完成大部分功能。但是openclaw也经常会将自己搞挂，一个主要的原因是模型幻觉通过会导致openclaw将自己的网关配置（openclaw.json）搞错，导致网关挂掉，openclaw也就失去了进一步调试正确的可能性。这里我提供三种解决方法：

方法一：在openclaw记忆文件中添加要求，每次修改openclaw之前都需要用户进行确认。这种方法最简单，仅需要直接让openclaw记住即可。但是模型有时候可能会忽略这个规则。

方法二：在tool use之前添加hook，如果是修改config则触发规则判断，格式没有问题后再允许claw修改自己的配置。

方法三：设置一个守护进程，检测打claw的gateway当机后，主动触发\`\`\`openclaw gateway doctor --fix\`\`\`命令修复网关配置

## 三、成本考量与优化策略

### 3.1 使用成本

这里我想说的是openclaw真的非常非常耗token，我最开始使用的copilot pro订阅，用的claude sonnet 4.5模型，结果刚刚开始接入使用大概2-3天时间就将刚刚续费过的订阅额度完全使用光了，但是用ollama部署的本地模型效果又非常差（当时使用的gpt-oss:20b）。刚好当时qwen3.5发布，百炼正在搞活动，就接入尝试下，仅仅一天就耗光了100万免费的token以及之前账户里剩余的20RMB，无奈又充值20RMB后，仅一个操作（当时应该是让openclaw自己安装antfarm）就收到了欠费告警。大概3-4天的使用，我不仅花光了copilot pro订阅的流量，用完了qwen3.5的免费额度，还充值了66RMB，最后消耗光后订阅了百炼的code plan，第一个月还有些优惠。

![](/assets/images/posts/openclaw-use/m1hVO-RN0RIL5teYNVEkqVGh-CMJpxttbMaDR-BRmSg=.png)

因此这里建议，最好去云平台（阿里百炼、字节火山、GLM、Kimi、MiniMax）等平台买下订阅，一个月一般40-50RMB，不是重度使用一般个人应该足够使用。超了之后可以配置自动切换到本地模型，我自己使用的max studio，可以部署80B左右的模型。

### 3.2 如何有效减少成本

那使用openclaw又没有什么方式能减少使用成本呢，这里我主要提供一下三种方式：

1. **利用好各模型厂商的免费额度**：当新模型发布后为了获取用户，模型厂商一般会提供一定的免费额度或者送一些优化券，如春节这次qwen3.5发布百炼平台就提供了每个模型100w的免费token（虽然不太够用），之前kimi模型发布、minimax都送过使用优惠券，可以关注并好好利用。
2. **部分任务使用本地模型**：openclaw是支持多agent的，对于一些简答的任务可以配置使用本地完成，比如仅做一些信息检索和收集可以使用openai的gpt-oss:20b模型配置web search就已经有比较好的效果了，一些简单的code理解也可以使用本地code模型来做。尽量减少云模型的调用。
3. **优化openclaw**：openclaw消耗token过快本质是所有任务都通过模型完成。其实对于一些重复性的工作完成可以让openclaw生成工具来自动完成，这样就不用每次都消耗token，尽在构建工具和调试时消耗较多的token，通过这种方式我目前的百炼订阅额度还十分充裕。其次虽然openclaw有上下文压缩策略，这里还是建议新任务主动通过/new 命令创建新的会话，一方面可以减少无法上下文消耗输入token，也可以提升模型回复的效果。



## 四、构建个性化AI助理：Openclaw 实践指南

### 4.1 构建步骤（Step by Step）

这里为了大家部署的时候尽量少踩坑，我把自己部署的过程分享出来给大家参考。因为直接将openclaw部署到自己的电脑上，风险过高，这里为了规避可能的安全风险，我选择将openclaw安装在虚拟机中防治操作失误或者其他风险因素导致系统受损。同时尽量避免将个人信息等透露给openclaw。

#### 4.1.1 安装虚拟机

这里我使用的[lume](https://cua.ai/docs/lume/guide/getting-started/introduction)安装，要安装Lume虚拟机，首先通过Homebrew安装Lume (`brew install lume`)，然后使用`lume create`命令创建虚拟机并配置操作系统、CPU、内存和磁盘大小，最后通过`lume run`或`lume start`启动即可。

```shellscript
brew install lum
```

```shellscript
lume create openclaw --os macos --ipsw latest \
  --cpu 8 \
  --memory 16GB \
  --disk-size 50GB
```

这里建议disk-size设置大一些，随着给到openclaw的工作越来越多，disk使用增长会很快，尤其是需要安装工具、模型的情况下。上周我刚刚对虚拟机的磁盘进行了一番扩容。

#### 4.1.2 登陆虚拟机安装openclaw

## 五、Openclaw 生态与未来展望

### 5.1 生态系统概览


当前围绕openclaw，社区正在构建一个持续进化的生态系统，旨在赋能用户获取技能、优化工作流程并探索创新工具，充分展现其强大的可扩展性与无限的未来发展潜力。

* **ClawHub**

**ClawHub** 是 OpenClaw 生态的官方技能市场（skill registry），类似 Chrome 扩展商店 。 ClawHub 为openclaw提供可下载的 Skills（技能插件）。用户可通过 `clawhub` CLI 工具或网页（clawhub.ai）搜索、安装社区开发的技能，目前已有超过 3,000 个 Skills 。每个 Skill 以 Markdown 格式封装，透明可读，支持多模型后端（Claude、GPT 等）。

* **EvoMap**

**EvoMap** 是全球首个 AI Agent 经验共享网络协议，基于 **GEP（Genome Evolution Protocol，基因组进化协议）** 构建 。它允许 Agent 将学到的经验封装为"基因胶囊"（Gene Capsule），包含完整决策链路、环境指纹和审计记录，实现跨 Agent 的能力遗传与共享 。项目源于 OpenClaw 社区开发者开发的 Evolver 插件——该插件曾 2 小时登顶 ClawHub 下载榜，后因平台风波下架 。EvoMap 采用去中心化设计，任何平台均可接入，内置自然选择机制筛选优质胶囊，目前已获数百万美元天使轮融资。

## 六、使用 Openclaw 的个人建议与风险规避

### 6.1 个人建议

在享受Openclaw带来便利的同时，用户需要警惕潜在的安全风险，并采取渐进式、可控的方式进行探索和实践。

* 首先保证隔离性（高度自由、权限太高、生态很开放可能被黑客利用），不要让Openclaw把你的系统搞坏或者被攻击。
* 从外部获取信息或者发送时，要求Openclaw进行安全审核。
* 从小场景、使用成本低的方式开始逐步尝试，防止消耗过快。
* 你始终需要了解Openclaw的实现和配置，尤其是在初期，当Openclaw把自己搞坏时可以修复它。
* 始终确保Openclaw真正完成了任务，可以要求它进行检查。
